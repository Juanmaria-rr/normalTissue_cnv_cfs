1 · The shared question and its vocabulary

All three tests ask the same question: do copy-number breakends of normal breast cells fall inside a set of fragile sites more often than they would by chance? They differ in what they count, what “by chance” means and which confounders they neutralise. Running three tests is a way of checking that an answer does not depend on one arbitrary choice.

  • Breakend: the boundary between two segments of different copy-number state in one cell. Its position is uncertain by about one bin, so it is stored as an interval [lo, hi] (from the start of the last bin of the left segment to the end of the first bin of the right one).
  • Event: breakends of the same donor, chromosome, direction and type that lie within 2 Mb of each other, collapsed into one. A clone of 100 cells that inherited the same deletion is 100 breakends but 1 event: the break happened once.
  • Set: a list of genomic intervals (a CFS catalogue, a consensus, or a control such as genes > 1 Mb). “Overlap” means the breakend or event interval shares at least one base with any site of the set.
  • O, E and fold: O is how many events overlap the set; E is how many would overlap if the events had been placed at random under a defined null; fold = O / E. A fold of 1 means “as expected”, 2 means “twice as often as expected”.
  • Subsets: every test is run per bin size (200 kb, 500 kb, 1 Mb), direction (loss, gain, all) and deviation stratum (E1–E4; “main” = E2–E4, the paper's 1.3 / 0.7 ratio threshold). Only interstitial events (not touching a centromere) enter.

Why a null at all. Simply counting overlaps says nothing: a set that covers 10% of the genome will catch about 10% of random events. Worse, fragile sites are not random places: they are late-replicating, AT-rich, often inside very large genes, and they are unevenly spread across chromosomes. Copy-number breaks (and copy-number calling artefacts) follow some of the same features. A useful null must therefore place random events in genomic context comparable to the real ones. The three tests do this in different ways.

2 · Test A: positional permutation of events

Script scripts/06_enrichment/test_a_permutation.py · unit: one collapsed event · worked example: interstitial E2–E4 losses at 500 kb against macheret2020:HS68 (MiDAS domains of HS68 normal fibroblasts, Macheret 2020).

The idea in one sentence. Take each real event and ask: if this exact event (same chromosome, same width, same replication timing) had happened somewhere else, how likely would it have been to hit a fragile site? Sum those probabilities over all events and compare with how many actually hit one.

Step 1 · One event, its null placements and its pi

  1. The event: donor P07, a loss with interval chr7:67.00–69.50 Mb (width 2.50 Mb), overlapping the HS68 site(s) annotated ONE_GENE:AUTS2;f in Macheret et al. 2020. Its replication timing (mean RT of the usable bins of the interval) falls in quintile Q2 of the usable 500 kb bins (Q1 = latest replicating fifth of the genome).
  2. Allowed alternative positions: the event, with its width kept, is started at every usable 500 kb bin of the same chromosome (the observed intervals also start at a bin start, so placements sit on the same grid). For each placement the RT is computed exactly as for the event (mean RT of the usable bins it covers), and only placements in Q2 are kept; placements touching the pericentromeric block ± 1 Mb are removed. That leaves 86 placements.
  3. Of these, 13 overlap an HS68 site. All placements are equally likely, so the event's null probability of overlap is exact, no simulation needed: pi = 13 / 86 = 0.151.
  4. Observed: the real interval does overlap a site, so oi = 1.

Step 2 · All events: observed O and expected E

The same is done for each of the 93 interstitial E2–E4 losses at 500 kb. Most have pi close to 0 (median 0.012) because HS68 sites cover little of the genome. Then:

O = Σ oi = 10 events overlap a site
E = Σ pi = 2.48 events expected to overlap by chance
fold = O / E = 10 / 2.48 = 4.03

Step 3 · Is O = 10 surprising? The p-value

Under the null each event overlaps independently with its own probability pi, so the number of overlaps S is a sum of 93 unequal coin flips (a Poisson-binomial distribution). Its distribution can be computed exactly, by convolving the events one at a time, so no simulation is needed: p exact = P(S ≥ 10).

Confidence interval of the fold. The 93 pairs (oi, pi) are resampled with replacement 2,000 times and O/E recomputed: fold 4.03 [2.11–6.28]. It reflects how much the fold depends on which events happened to be sampled, not uncertainty in the site set.

The permutation p (the reference p-value). Events are not independent: a donor's recurrent losses, nearby events and the clustering of sites along the genome all make the exact p too optimistic. So the HS68 set itself is shuffled 5,000 times (every site moved to a random usable bin of the same chromosome and RT quintile, width kept) and test A is re-run on each shuffled set. The shuffled folds have median 1.10 and 2.5–97.5% range 0.00–2.60; the real set gives 4.03. p perm. = (1 + shuffles with fold ≥ 4.03) / (5,000 + 1) = 4.0e-04, against p exact 1.2e-04. The shuffles centring near 1 also checks that the null is not biased.

Multiple testing. This is one of about 200 main-stratum tests (sets × bins × directions). Benjamini–Hochberg gives q family = 0.0048 (only within the HS68 set), q global = 0.023 (all sets) and q perm. global = 0.079 (all sets, on permutation p). With no set chosen in advance, the global values are the ones that control the error.

What it answers

Do events (each break counted once, however many cells inherited it) overlap the set more than events of the same width and replication timing placed elsewhere on the same chromosome?

How large is the excess (fold) and how consistent across bins, directions and strata?

What it does not answer

Whether the excess is explained by large genes, GC or mappability (only RT and chromosome are matched): that is test B.

Whether one donor or one expanded clone drives it: that is test C (and the leave-one-donor-out runs).

Which individual event is due to fragility: a fold of 4.0 with 10 overlaps still means some of the 10 would be there by chance (E ≈ 2.5).

Limitations of test A

  • RT is the only genomic covariate. Fragile sites concentrate in very large, late-replicating, transcribed genes. Matching RT removes part of that, not gene size or transcription.
  • Independence. The exact p and the event bootstrap assume each event's overlap is independent. Events of the same donor or region may not be; clonal collapse removes the most obvious dependence, the permutation p keeps the clustering of events, and a bootstrap over donors (in test_a.tsv) shows the spread between donors.
  • Coarse positions. Event intervals are 0.5 to several Mb wide, comparable to the sites. A wide interval overlaps more easily; the null keeps the width so this is fair, but it limits how precisely a break can be assigned to a site.
  • Many sets, many subsets. q family corrects within one set only; q global and q perm. global correct across all sets. With no pre-registered hypothesis, one isolated small p is a lead, not a finding.
A null that could not reproduce the observation (fixed 5 November 2026). In the first version, null placements were centred on single bins that had to be in the event's RT quintile, while the event's quintile came from the mean RT of its whole interval. An event spanning a Q5 and a Q3 bin averaged to Q4, none of its own bins was an allowed centre, and it got pi = 0 although it overlapped a site: +1 to O and 0 to E. The null now places intervals on the same bin grid and computes their RT exactly as for events, so every event can land where it was observed. 3 · Test B: regression on genomic windows

Script scripts/06_enrichment/test_b_regression.py · unit: one 1 Mb window in one donor · same worked example (E2–E4 losses at 500 kb, macheret2020:HS68).

The idea in one sentence. Cut the genome into windows, count events in each, and ask whether windows that contain a fragile site have a higher event rate after accounting for the other things that make a window break-prone (RT, GC, mappability, chromosome, donor, and optionally large genes). It is the regression counterpart of test A: instead of matching on RT it adjusts for several covariates at once.

Step 1 · Build the table: one row per donor × window

The genome is divided into the usable 1 Mb windows outside pericentromeric blocks ± 1 Mb: 1,917 windows, the same for the three event bin sizes. With 5 donors that is 9,585 rows. Each event is assigned to the eligible window with which its interval [lo, hi] overlaps most. 3 of the 93 events overlap no eligible window (non-usable or too close to a centromere) and drop out, leaving 90. For each window the script records:

What is counted. Windows of chromosome 7 around the event drawn in test A (P07, chr7:67.0–69.5 Mb); the donor columns are the number of E2–E4 loss events assigned to the window. How. RT, GC and mappability are the means of the 50 kb annotation of sWGS_relativeCN, z-scored over all windows; “fraction in genes > 300 kb” from refGene loci; usable fraction = share of the window's 50 kb bins that pass the QDNAseq filters (used as an offset). Limitations. Overlap with the set is yes / no, whatever fraction of the window the site covers.

This is the incidence rate ratio (IRR) of the set. The crude model (events ~ feature + donor, with the usable fraction as offset) gives practically the same number, IRR 3.69 [1.83–7.46], because donor only shifts the baseline rate and almost every window is fully usable.

Note that 9 events fall in HS68 windows here, against 10 overlapping events in test A. The two tests define “hitting the set” differently: test A asks whether the event interval touches a site, test B whether the window the event is assigned to overlaps a site.

Step 3 · Adjusting for what else makes a window break-prone

HS68 windows are not average windows. Their mean covariates (z-scores; genes as a fraction):

Two adjusted models are fitted:

adjusted: log E[events] = β·feature + γ1·RT + γ2·GC + γ3·mappability + chromosome + donor + log(usable fraction)
adjusted_genes300: the same + γ4·genes300
IRR = exp(β)

Result: adjusted IRR 3.40 [1.46–7.90], p = 0.0045, q family = 0.022, q global = 0.38; adjusted_genes300 IRR 3.99 [1.70–9.37], p = 0.0015 (IRR of genes300 0.58, of RT 1.38 per SD). Large genes are probably part of how fragile sites break (a mediator, not only a confounder), so adjusting for them is conservative: it can remove part of the very effect being tested.

Which distribution and which errors. Counts are modelled as negative binomial if they are more variable than Poisson. Here the estimated over-dispersion is negative (α = -1.08): almost every donor × window has 0 or 1 events, so the model is Poisson (family = poisson, as in 1053 of the 1053 fitted models). Windows of one chromosome are not independent, so the standard error of the set is computed both from the model and cluster-robust by chromosome, and the larger of the two is used (cluster here). When no event falls in windows of a set the model has no finite estimate (separation) and the row is left empty instead of reporting p = 0.

What it answers

Is the event rate higher in windows that contain the set, after adjusting for RT, GC, mappability, chromosome and donor?

How much of it remains when large genes are adjusted for too? (Compare adjusted and adjusted_genes300.)

What it does not answer

Anything about the exact position of a break inside the window: an event counts in one window only.

Whether one clone drives the result (events are collapsed, as in test A).

Limitations of test B

  • Fixed 1 Mb grid. A site near a window border may be credited to the neighbouring window; 3 of 93 events in this example overlap no eligible window and are excluded.
  • Binary overlap. A window touched by 20 kb of a site counts the same as one fully covered.
  • Sparse counts. With few events and many fixed effects (22 chromosomes, 5 donors), estimates are unstable for small sets; CIs are wide.
  • Linear covariates. RT, GC and mappability enter linearly on the log scale; a non-linear effect of RT is only partly removed (test A's quintile matching is more flexible for RT).

4 · Test C: per breakend and per donor

Script scripts/06_enrichment/test_c_per_donor.py · unit: one breakend of one cell (no collapsing) · same worked example, then the gains of the same set.

The idea in one sentence. Repeat test A's observed / expected comparison, but count every cell's breakend (so an expanded clone weighs as many times as it has cells) and compute it separately for each donor, to see whether the excess is shared or driven by one donor.

Step 1 · Same pi, different unit

Each breakend gets o (does its interval overlap the set?) and p (its exact null probability, computed exactly as in test A from its own chromosome, RT quintile and width). Then per donor Od = Σo, Ed = Σp, ratio Od/Ed. The pooled ratio is ΣO / ΣE over all donors.

Why this matters: clones. The breast epithelium contains expanded clones. Breakends per event by donor and direction (500 kb, E2–E4):

The largest single event is a gain in P08, chr6:66.0–71.5 Mb, present in 203 cells. In tests A and B it counts once; in test C it counts 203 times. Test C asks “are the copy-number changes we observe in cells enriched?” (which mixes break rate with clonal expansion), while A asks “are the break events enriched?”.

Step 2 · Per-donor ratios and their uncertainty

Pooled: O/E = 11 / 3.37 = 3.26 [1.82–4.62]. 4 of the 5 donors point above 1 (P07 5.67, P08 2.70, P18 3.97, P20 0.95, P36 4.50). With 1–5 overlaps per donor, every per-donor estimate is very imprecise.

Step 3 · Do donors disagree? The heterogeneity test

If all donors shared the pooled ratio R, donor d would be expected to show R·Ed overlaps. The test sums the squared deviations from that, Pearson style, over donors with Ed ≥ 1 (the others are too small to say anything):

R = 11 / 3.37 = 3.26
P20: (1 − 3.26 × 1.05)² / (3.26 × 1.05) = 1.72
only 1 donor with E ≥ 1: df = 0, the test cannot be computed

Here the per-donor expected counts are too small for the test; the per-donor ratios above are the only information on consistency between donors.

Step 4 · When A and C disagree: the gains

For gains against the same set, test A gives fold 1.21 (6 / 4.95 events). Test C gives pooled 0.41 (7 / 17.04 breakends), and P08 alone 0.34 (5 / 14.71, 561 breakends in 255 cells). P08's gains are dominated by a few large clones (the 203-cell event above among them) whose breakends carry a sizeable null probability but do not overlap a site; counted once per cell, they add many times to E and nothing to O, swamp the other donors and pull the pooled ratio below 1. Pooling losses and gains, test C's heterogeneity p is 5.5e-05. This is the kind of discrepancy test C exists to expose: a ratio driven by one donor's clonal structure, not by break location.

Change from the original plan. The plan was a mixed logistic model (breakend overlaps ~ set, with a donor random effect). With five donors the random-effect variance cannot be estimated, so the test reports per-donor ratios plus this heterogeneity test.

What it answers

Is the enrichment present in each donor, or carried by one?

Does the result change when every cell's breakend counts (i.e. weighting by clonal expansion)?

What it does not answer

Whether the break rate itself is higher at sites: clonal expansion and selection are mixed in.

A formal population-level estimate: five donors are too few for a random-effects model.

Limitations of test C

  • Clones dominate. One expanded clone can outweigh all other donors; the pooled ratio then describes that clone.
  • Dependence within clones. The bootstrap resamples cells as if independent; cells of one clone share one event, so the CI is too narrow when clones are large.
  • Few donors. Five donors, of which often only one or two have E ≥ 1: the heterogeneity test has very little power.
  • Same null as test A. It inherits the RT-only matching.
